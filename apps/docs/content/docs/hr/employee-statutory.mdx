Every employee profile has a **Statutory info** tab that holds the tax and payroll-affecting data the payroll engine needs. The fields are country-neutral — the country payroll rules (Guyana: GRA) interpret them.

## Where to find statutory info

Go to **App → Employees**, click the employee, then open the **Statutory info** tab.

<Callout type="warn">
  This tab is only visible to HR Admin, Payroll Admin, Tenant Owner, and Tenant Admin.
  Managers and employees don't see it.
</Callout>

## Fields

| Field | What it holds |
| --- | --- |
| Tax identification number | The employee's statutory tax ID. In Guyana this is the TIN. |
| Social security number | The statutory social-security ID. In Guyana this is the NIS number. |
| Dependent children | The number of dependent children. Directly affects the payroll child allowance calculation. |
| Has second job | Whether the employee has a declared second income, and the second-job pay amount. Affects tax treatment. |
| Medical: on file | Whether a medical certificate is on file. |
| Medical: payroll deduction | Whether a medical premium is deducted through payroll. |
| Medical: external premium | Whether the employee pays their medical premium outside payroll. |
| Other deductions | A recurring deduction amount not covered by the other fields. |

## How it affects payroll

**Dependent children** is the most significant field for payroll calculations. Each dependent child may qualify the employee for a child allowance under the country's tax rules. If this number is wrong, the employee's net pay may be too high or too low.

The second-job declaration and medical deduction fields feed into tax and deduction computations for the relevant pay period.

If any statutory field is missing when a payroll run is processed, the engine applies the statutory default (usually zero). Correct the value before the next run to ensure accuracy.

## Who can see and edit statutory info

Statutory identifiers (TIN, NIS/social security number) and bank account numbers are **masked by default** for most roles. Only Payroll Admin, Tenant Owner, and Tenant Admin see the full unmasked values.

| Action | Who |
| --- | --- |
| View the Statutory info tab | HR Admin · Payroll Admin · Tenant Owner · Tenant Admin |
| See full TIN / NIS (unmasked) | Payroll Admin · Tenant Owner · Tenant Admin |
| Edit any statutory field | HR Admin · Payroll Admin · Tenant Owner · Tenant Admin |

<Callout type="info">
  Masking is enforced on the server. The masked value is sent to the browser — the
  full identifier never reaches non-payroll sessions.
</Callout>

## Correcting a wrong value

<Steps>
<Step>Go to **App → Employees** and open the employee's profile.</Step>
<Step>Click the **Statutory info** tab.</Step>
<Step>Click **Edit** and update the field.</Step>
<Step>Save. The corrected value takes effect on the next payroll run.</Step>
</Steps>

<Callout type="warn">
  Changing the **Dependent children** count mid-cycle affects payroll from the next run
  onward. It doesn't retroactively recalculate issued payslips. If a past payslip was
  calculated with the wrong count, use the payslip correction workflow to issue a
  corrected payslip with the right values. See [Effective-dated rules](/docs/payroll/effective-dating).
</Callout>

## No-login employees and statutory data

No-login employees (those without an email or system account) have statutory records just like any other employee. Their payroll is calculated, their TIN/NIS is stored and masked by role, and their dependent children count feeds into the allowance calculation. The absence of a login doesn't affect any of this.

See [Employees — no-login employees](/docs/hr/employees#no-login-employees) for how to give a no-login employee system access when needed.

## Troubleshooting

**The Statutory info tab isn't visible.** Your role doesn't have permission to view it. Only HR Admin, Payroll Admin, Tenant Owner, and Tenant Admin can see this tab.

**TIN or NIS shows as masked.** You're seeing the masked value because your role is not Payroll Admin or above. If you need the full value to verify it with a government authority, ask a Payroll Admin to confirm it.

**Dependent children count is wrong and it affected a past payslip.** Correct the count on the profile first so future runs are right. Then raise a payslip correction for any issued payslip that used the wrong value.

**The employee has no statutory record at all.** Open the Statutory info tab — if no values are set, click **Edit** and enter the relevant fields before the next payroll run.
